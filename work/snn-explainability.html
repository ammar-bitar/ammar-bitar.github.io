Which spikes does a spiking network actually use?

Adapting gradient-based attribution to spiking neural networks, and finding that a small fraction of the input spikes carries the decision.

Where
Intel Labs, Munich, 2020 to 2022
Scope
Adapting the attribution methods, building and training the spiking networks from scratch, designing and running the perturbation experiments, writing the paper
Published as
Bitar, Rosales, Paulitsch. Frontiers in Neuroscience 17, 2023, first author, supervised by Rafael Rosales and Michael Paulitsch
Hardware
Networks trained on GPU with surrogate gradients, and run on Intel Loihi
About the figures
The diagrams and interactive pieces here are built for this page: working simulations of the ideas, written from scratch so you can play with them.

01The problem

Spiking neural networks process events, not frames. A neuron fires when its membrane potential crosses a threshold, and the network's input is a sparse stream of spikes over time. That sparsity is what makes them cheap to run on neuromorphic hardware. It also makes them hard to explain: the attribution methods that work for conventional networks assume a dense, real-valued input and a differentiable forward pass, and spikes are neither.

Existing explainability methods for spiking networks had four common limitations: they scaled poorly, only worked on convolutional layers, needed a second model to be trained, or produced activation maps instead of attribution maps. An activation map shows what fired; an attribution map shows what influenced the prediction. The aim was a method without these limitations.

02The method

The networks were trained with backpropagation through time using surrogate gradients: on the backward pass only, the non-differentiable spike is replaced by a smooth function around the threshold. A network trained this way already provides a gradient of the output with respect to every input spike. That makes it possible to adapt two gradient-based methods from conventional networks, Saliency and Integrated Gradients, to the spatio-temporal input and get an attribution score for every pixel at every timestep.

The event stream also has to be turned into something a network can take, and we compared several event-frame representations: plain time binning, where events in a window are counted per pixel and polarity; 3D and 4D voxel grids, which keep a time axis (and polarity as a fourth dimension) so the network sees the order of events inside the window; and leaky binning, where each event adds to a value that decays over time, so recent events weigh more. The choice matters, because it decides how much temporal structure reaches the network and it changes which input features the attribution points at.

An attribution map needs to be tested, so we ran perturbation experiments at the pixel level for frame data and at the spike level for event data: remove the spikes the method ranks highest, re-run the network, and measure how much the prediction changes. A good method changes the prediction after very few removals; a poor one does no better than removing spikes at random.

03What we found

On CIFAR-10 and DVS128-Gesture, across the neural codings we tested, removing the highest-ranked spikes flipped the prediction after fewer than 5% of the spikes were gone. The decision depends on a small part of the input, and the method finds it. Model-agnostic methods such as LIME and RISE, which need many forward passes per explanation, took two to three orders of magnitude more compute for the same task.

The second finding was that the coding or representation, meaning how a real-valued input is turned into spikes or how an event stream is binned into frames, changes which input features matter. Two networks trained on the same images with different codings rely on different parts of them. This matters whenever a spiking model has to be explained in a real application.

04Two directions of encoding

The two datasets needed opposite preprocessing.

DVS128-Gesture is already event data. Each recording is a stream of (x, y, t, polarity) tuples. The networks took either the raw stream, timestep by timestep, or one of the event-frame representations described above. Either way a spike is an element of the input tensor, so the perturbation experiments could remove spikes one at a time and re-run the prediction.

CIFAR-10 contains images, so each pixel has to be encoded as a spike train before a spiking network can use it. We used five neural codings:

  • Rate coding. Spike count over the window is proportional to intensity, evenly spaced. Robust and easy, but it uses many timesteps to say one number.
  • Poisson coding. Each timestep fires with probability proportional to intensity. Same information in expectation, with the randomness of a real sensor.
  • Time to first spike (TTFS). One spike per pixel; brighter fires earlier. Very sparse, and the meaning is in the latency.
  • Time to last spike (TTLS). The mirror image: timing is measured from the end of the window.
  • Phase coding. Timesteps within a period carry weights, and a pixel fires at the phases matching its intensity's binary digits, so a full value is transmitted in one period.

We computed attribution maps for networks trained with each coding, and for the same images they highlighted different pixels. An explanation of a spiking model therefore only holds for the coding it was computed with.

05Hardware and the lab

Intel brought me in to build up the lab's neuromorphic hardware and software expertise ahead of the opening of its Munich neuromorphic laboratory. Alongside the attribution work I ran models on Loihi and wrote the team's tutorial notebooks on how spiking neuron models differ from standard deep learning and how STDP and surrogate-gradient training map onto the hardware. The notebooks became part of the lab's documentation.
